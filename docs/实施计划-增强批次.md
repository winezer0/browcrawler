## 三、关键接口设计

### F1 safety（crawl/safety.go）

```go
type Safety struct{ urlSkip, formSkip []*regexp.Regexp }

func NewSafety(enabled bool, extraURL, extraForm []string) (*Safety, error)
func (s *Safety) SkipURL(u *url.URL) bool        // 入队前判定：true=记录发现但入队跳过
func (s *Safety) SkipForm(formHTML string) bool  // SubmitPageForms 前判定：跳过提交仍记录
```

内置默认正则（Argo 词表基线）：URL `logout|signout|sign-out|注销|登出`；表单
`password_new|old_?pass(word)?|修改密码|重置密码|delete_?(user|account)|删除用户|删除账号`。
行为语义与 Argo 对齐：**发现不受损**——被 skip 的 URL/表单仍进 discovered，标
`source=form-skipped` / 入队日志注明，只是不真实触发。
配置：`crawl.safety.enabled`（默认 true）、`safety_url_skip`/`safety_form_skip`
追加正则；CLI `-no-safety`。

### F2 运行时路由捕获（crawl/runtime_route.go + driver.go）

```go
// driver.go 新增可选能力接口（与 FormSubmitter/InteractionTrigger 同模式）
type HookInjector interface {
    InjectOnNewDocument(ctx context.Context, js string) error // 每次导航自动注入
    ReadAndClearRoutes(ctx context.Context) ([]string, error) // 读走并清空
}
```

hook JS（常量，框架无关）：包装 `history.pushState/replaceState` + 监听
`hashchange`，新 URL push 进 `window.__browcrawler_routes`。Go 侧收集点：每次
settle 后 + 每次交互点击后；normalize 去重后作为
`Discovery{source:"runtime-route"}` 写 discovered 并回灌队列（scope 内）。
配置：`crawl.runtime_route`（默认 true——纯观察零风险）。
注入机制依赖 rod `Page.AddScriptToEvaluateOnNewDocument`，Obscura/Chrome 通用。

### F3 waitlogin

CLI `-waitlogin`：强制有头浏览器（Chrome 后端加 `--no-headless` 变体 / Obscura
有头模式待验证，实施时确认）；首屏 settle 后暂停，stdout 提示人工登录，stdin
等回车后继续 BFS。会话/Cookie 天然保留在同一浏览器会话。与 `-creds`/`-auth-file`
互补不互斥。stdin 非终端（CI/管道）时自动跳过等待并告警（Argo 同款行为）。

### F4 域外导出（storage/outscope.go）

`ExportOutScope(path)`：InScope==false 的记录输出 URL 列表（每行一条，带状态码
注释）。OutputPaths.OutScope + CLI `-deliver-outscope`；多会话沿用 withSuffix。

### F5 secrets + SARIF（storage/secrets.go）

```go
type Rule struct{ Name, Pattern string; Severity string; Validate func(match string) bool }
type Finding struct{ Rule, URL, Masked string; Confidence float64 }
func ScanRecords(records []Record, rules []Rule) []Finding      // 响应体 + 落盘 JS
func (r *Recorder) ExportSecrets(base string, findings []Finding) error // .txt/.json/.sarif
```

内置 30–50 条高置信规则（AWS 前缀族/Stripe 形状/GitHub CRC32/JWT 头结构/私钥
PEM/Slack/Twilio…借用对标已核实的 Provider 校验思路做形状验证防误报）；打码
保留前 4 后 4。数据源：records 内存快照（body 已有）+ out/js 落盘文件。默认关，
CLI `-secrets`；SARIF 2.1.0 供 GitHub code-scanning。自定义规则走
`secrets.rules` yaml（P1 的规则配置化随此一并实现）。

### F6 WS 帧捕获（storage/ws.go + driver.go）

```go
type WSCapturer interface {
    EnableWSCapture(ctx context.Context, onEvent func(WSEvent)) error
}
type WSEvent struct{ ReqID, URL, Kind string /*created|handshake|frame|closed*/
                     Direction, Opcode, Payload string; Seq int; Code int; Reason string }
```

RodDriver 用 `page.WaitEvent` 族 / `browser.EachEvent` 订阅
`NetworkWebSocketCreated/HandshakeResponseReceived/FrameReceived/FrameSent/Closed`。
帧写入 JSONL：`resource_type=websocket` + `ws` 对象（握手/帧/关闭三类事件，
文本帧原文、二进制 base64，受 max_body 限额）。默认开（纯观察）；帧不进
requests.txt（HTTP 重放语义不适用），report 增 `ws_sessions` 计数。

### F7 -feed（crawl/feed.go）

```go
type FeedSeed struct{ URL, Method, Kind string } // Kind: chunk|route（容错未知）
func LoadFeed(path string) ([]FeedSeed, error)
```

Run 时 feed 项在 seed 队列初始化后插入：scope 内 + seen 去重后入队。**诚实边界**：
浏览器导航只支持 GET——`Method != GET` 的 feed 项记录为
`Discovery{source:feed, confidence:"interface"}`（发现未请求），这正是 Argo
"未请求"语义的对齐。JSONL 解析容错：非 JSON 行跳过、缺 URL 字段跳过。

## 7. F2 实施结果：运行时路由捕获（2026-11-11，已完成）

### 7.1 包结构（按框架分包，用户指定）

```
internal/routeruntime/
├── runtime.go        # Collect 调度：跑全部探针 → JSON 解析 → 去重
├── probe/probe.go    # 共享类型（叶子包，消除父/子包循环依赖）
├── vue/              # Vue3 __vue_app__.$router.getRoutes()（含动态 addRoute）+ Vue2 __vue__ 遍历
├── react/            # Remix/RR7 __remixManifest.routes；纯 CSR 靠 generic
├── angular/          # window.ng（dev 构建）；生产靠 generic
├── next/             # Pages Router window.next.router.components
├── nuxt/             # Nuxt2 $nuxt.$router / Nuxt3 useNuxtApp().vueApp.$router
├── sveltekit/        # __sveltekit* 调试对象（尽力而为）；生产靠 generic
└── generic/          # 框架无关：pushState/replaceState/hashchange hook + location
```

### 7.2 采集编排

- `AddScriptToEvaluateOnNewDocument` 注入 generic hook（SPA 编程式导航必经 API）
- 每页 settle 后 + 每次交互点击后各收集一轮；探针结果为站内路径，相对 seed 解析为绝对 URL
- 双层语义照旧：discovered 记录（`source=runtime-route:<框架>`）+ scope 内 depth 闸门内回灌队列
- 只读约束：只读框架路由对象，不执行业务代码

### 7.3 实施中修复的三个问题

1. 探针写成 IIFE——rod Eval 以 `(fn).apply` 调用，必须传**函数定义**（同 forms.go 的教训）
2. Default() 未置 RuntimeRoute=true（替换锚点未命中），首测全空
3. 回灌未受 depth 闸门约束（depth=0 也导航）——与 links 入队同规则修复

### 7.4 在线验证（已知公开站点，经 10808 代理实测）

| 站点 | 框架 | 运行时路由捕获 | 说明 |
|---|---|---|---|
| **nuxt.com** | Nuxt3 | **328 条**（首页） | useNuxtApp 探针在生产构建可用——最大验证点 |
| nuxt.com depth=1 | Nuxt3 | pages=7 failed=0 | 路由真实回灌导航：361 不同路径、943 条流量请求包 |
| nextjs.org | Next App Router | 0 | App Router 无 window.next（Pages Router 才有）；`__next_f` 归 assetcrawler 静态 |

## 8. 决策记录：运行时路由主动执行——browcrawler 不做（2026-11-11）

> 背景：评估 assetcrawler `-route-exec`（goja 执行 webpack 自注册 chunk 物化
> 路由表，opt-in 默认关）是否应在 browcrawler 重复实现。F1 safety 的未提交实现
> 已按指示撤销，本决策同时确认 F1 回到待办。

**结论：不实现。** 论证：

1. **browcrawler 的浏览器已经在执行目标 JS**。"跑 chunk 拿路由表"在无头解析器里
   是补执行能力，在浏览器里是既成事实——chunk 加载/路由注册/守卫放行全部
   原生发生，F2 探针+hook+interactions 就是在读取这个执行结果。重复造执行器
   没有增量。
2. **残差缺口（未访问的懒加载 chunk 内运行时注册的路由）已有覆盖路径**：
   - assetcrawler `-route-exec`（opt-in 主动同意）负责主动物化；
   - `-feed`（F7）把 chunk/路由候选回灌 browcrawler 真实打开；
   - interactions 点击让懒加载自然发生。
3. **browcrawler 侧的等价实现（页面上下文强制调用 webpack require）弊大于利**：
   执行目标代码 + 构造调用会改变页面状态、暴露自动化指纹、可能崩掉页面，
   换来的只是几条路由候选——收益/风险倒挂，且与 assetcrawler 能力重复。

**分工口径**：主动执行类能力归 assetcrawler（已有且 opt-in）；browcrawler 保持
"浏览器真实行为 + 只读录制"定位，两者经 -feed 闭环。F1 safety 回到待办首位
（真实站 form_submit 前提，实现思路已验证，确认后重做约 30 分钟）。

## 9. F6/F4 实施结果（2026-11-11）

### 9.1 F4 域外流量单独导出 ✅

- `--deliver-outscope`：自动生成 `<out>.outscope.txt`（每行 URL<TAB>状态码），
  内容为 in_scope=false 的录制子集——第三方资产清单（CDN/埋点/统计）。
- 端到端实测：`localhost:18080/outside-img 404` 入清单；verify O9 断言加入。
- storage.ExportOutScope 复用 records 内存快照 + InScope 标记；未启用 scope
  过滤时输出空文件（语义：全部域内）。

### 9.2 F6 WebSocket 帧捕获 ✅（含一个关键 rod 语义坑）

- 结构：`Record.WS`（event/created|handshake|frame|closed/error、direction、
  opcode、frame_seq、request_id）；帧 payload 文本原文/二进制 base64，受
  max_body 限额；WS 建连 URL 进报告（`ws_sessions` 计数），不参与 HTTP
  形状与 requests 重放（有状态会话协议，重放脚本另行设计）。
- 链路：Driver `WSCapturer.EnableWSCapture`（NetworkEnable + EachEvent 订阅
  created/handshake/frame sent|received/closed/error 五类事件）→ Crawler
  onWSEvent（requestID→URL 映射）→ Recorder.RecordWSEvent。双后端通用
  （CDP 事件与代理链路无关）。config `crawl.ws_capture` 默认开，`--no-ws-capture` 关。
- **rod 语义坑（关键）**：`EachEvent` 返回的 `wait()` 才开始消费事件流并分发
  回调——只 `go p.EachEvent(...)` 注册而不调 `wait()`，回调永远不触发。
  修复：`wait := p.EachEvent(...); go wait()`。隔离测试（同二进制同参数）
  5 事件全捕获（created + tick-0..3 received）后回灌修复。
- **诚实限制**：Obscura stealth 后端页面的 WS 连接不发起（stealth 网络层限制，
  与此前 SSE 发现一致）→ Obscura 下无帧可捕；Chrome 后端捕获链路经隔离测试
  验证正确，但本环境 Chrome 启动间歇失败（exit 3，既有问题）导致进程内 e2e
  暂未跑通，待环境稳定补验。
- 调试期间发现并修复：Default() 漏置 WSCapture/RuntimeRoute 布尔默认
  （YAML 缺键时为 false）、crawler.go 大括号失衡。

## 10. F1 实施结果：safety 危险操作防护（2026-11-11，已完成）

- **判定器** `internal/crawl/safety.go`：URL 正则（logout/signout/exit/quit/登出等，
  词边界防误伤）+ 表单 action/字段名联合匹配（password_new/confirm、
  delete[-_]?(user|account|post|article)、删除/改密中文词）；`--no-safety` 关闭；
  `safety_url_skip`/`safety_form_skip` 追加正则叠加；非法正则启动前报错。
- **语义「发现不受损」**：拦截项仍写 discovered（url-skipped/form-skipped），
  只是零真实流量。e2e 实测：两个危险表单 form-skipped、/logout url-skipped、
  危险端点零流量、正常搜索表单照常提交（GET /search?q=test）。
- **验证**：单测 2 组（词表命中/防误伤/关闭放行/追加正则/非法报错）；
  verify O10a（危险端点零触发）+ O10b（发现记录完整）固化；quick 18 PASS。
- **过程记录**：词表初版 `delete_?` 漏连字符形式（单测即出）；e2e 首跑失败
  根因是改词表后未重建二进制——不是代码问题。
